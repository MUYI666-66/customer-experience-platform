# 满意度评价运营平台 — 技术实现文档

## 一、项目概述

本项目为广东联通"满意度评价运营平台"，基于客户需求文档《AI预测模型开发需求-6.17.docx》构建，实现三大核心模块：

| 模块 | 核心能力 | 关键技术指标 |
|------|---------|-------------|
| **模块1：数据治理与特征工程** | 6大数据源接入，3层特征体系，预处理流水线 | 86基础特征 + 132衍生特征 + 50场景特征 |
| **模块2：AI预测模型** | 3个预测模型，批量+实时双模式 | 不满意预测≥80%，命中率≥10%，投诉预测≥85% |
| **模块3：满意度运营平台** | 五级下钻看板，闭环工单，案例库≥500，报表导出 | RBAC四角色，15分钟告警触发 |

## 五、关键算法与逻辑

### 5.1 不满意用户预测模型 (GBDT Ensemble)

```
输入特征: 86基础 + 132衍生 + 50场景 = 268维特征向量
模型架构: XGBoost + LightGBM + CatBoost 三模型加权融合
输出: risk_score∈[0,1], risk_level∈{high,medium,low}, TOP3根因

融合策略:
  final_score = 0.4 × XGBoost_score + 0.35 × LightGBM_score + 0.25 × CatBoost_score
  
性能目标:
  - 准确率 ≥ 80%
  - 实时推理 ≤ 1s P95
  - 批量推理 100K用户 ≤ 10s
  - PSI月漂移 ≤ 0.1
```

### 5.2 易受访用户预测模型

```
输入: 用户画像 + 历史调研 + 业务行为特征
模型: XGBoost + LightGBM + Logistic Regression 融合
输出: score∈[0,100], level∈{极高,高,中,低}

关键指标:
  - 月度输出 8.5万/100万限额
  - 命中率 ≥ 10% (实际: 13.2%)
  - 目标线: 10% (红色警戒线)
```

### 5.3 投诉时序预测 (LSTM + Transformer)

```
输入: 历史30天 × 多维时序特征 (区域/类型/基站)
架构:
  ┌─────────┐     ┌─────────────┐     ┌──────────┐
  │  输入层   │ ──► │ LSTM (时序)  │ ──► │ 全连接层  │ ──► 7天预测
  │ (30, 64) │     │ + Transformer│     │ (128→7)  │
  └─────────┘     │  (注意力)     │     └──────────┘
                  └─────────────┘

目标:
  - MAPE ≤ 15%
  - 72小时提前预警窗口
  - 4分类根因诊断: 网络故障/用户行为/业务问题/终端问题
```

### 5.4 SHAP特征重要性

```
算法: SHAP (SHapley Additive exPlanations) — 基于博弈论的模型解释方法

计算流程:
1. 对每个样本的每个特征计算Shapley值 (边际贡献)
2. 聚合所有样本得到全局特征重要性
3. 按贡献度降序排列 → TOP15特征

可视化:
- 水平柱状图 (蓝色=网络覆盖类, 红色=用户体验类, 绿色=用户画像类)
- 每个模型独立展示其TOP8特征
- SHAP值越大 → 对预测结果贡献越大
```

### 5.5 五级下钻

```
算法: 层级递归 + 面包屑导航

数据流: 全省 → 地市 → 区县 → 网格 → 基站 → 用户

状态管理:
  state.activeLevel: number (当前层级 0-5)
  state.selectedPath: string[] (选中的路径 ['广东省', '深圳市', '南山区', ...])

交互逻辑:
1. 点击层级Tab → 面包屑跳转回该层级
2. 点击数据项 → 下钻到下一层级 (更新activeLevel+1, path追加)
3. 未到达的层级Tab → disabled (cursor-not-allowed)
4. 面包屑底部展示完整选中路径

每层展示: 区域名 + 用户数 + 右箭头(非末层)
```

### 5.6 数据质量15分钟告警

```
触发机制:
  ┌──────────┐     每15分钟      ┌──────────────┐     score < 阈值     ┌──────────┐
  │ Cron调度  │ ───────────────► │ 质量检查脚本   │ ─────────────────► │ 告警触发  │
  └──────────┘                   │ completeness  │                     │ 钉钉/邮件 │
                                 │ accuracy     │                     │ 短信/平台 │
                                 │ consistency  │                     └──────────┘
                                 └──────────────┘

检测指标: 完整性(≥95%), 准确性(≥95%), 一致性(≥95%)
告警严重级别:
  - critical: 数据接入失败、预处理流水线异常
  - high: 推理超时、模型漂移(PSI>0.1)、命中率<10%
  - medium: MAPE超标、批量预测超时
  - low: 一般性提醒

响应目标: 15分钟内响应, 60分钟内解决
```

### 5.7 JWT认证

```
流程:
1. 客户端 POST /auth/token {username, password}
2. 服务端验证 → 生成JWT: Header{HS256} + Payload{user_id, role, exp} + Signature
3. 客户端存储token → 每次请求带 Authorization: Bearer <token>
4. get_current_user依赖: 解密token → 查用户 → 注入请求上下文

安全措施:
- 密码: bcrypt哈希存储 (passlib)
- Token过期: 可配置 (默认8小时)
- CORS: 限制origins白名单
- RBAC: require_admin装饰器保护敏感端点
```

                  ┌────▼──────┐
