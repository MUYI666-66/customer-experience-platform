## 1. 项目概述

本项目是一个 **中国移动客户体验分析平台** 的功能演示系统，包含两大组成部分：

| 部分 | 路径 | 说明 |
|------|------|------|
| **Python Demo 后端** | `demo/` | 真实运行的 Python 脚本，生成数据/图表/截图 |
| **React 前端展示** | `moss-lab/` | Vite + React 18 前端，将 Demo 产出包装为交互式展示 |

前端使用"数字苔藓"暗色主题（moss-green），通过 Three.js 3D 背景 + Framer Motion 动画 + 自定义 CSS 图表，营造有机/自然/高端的科技感。

**核心设计模式**: `PipelineRunner` 是一个纯展示型通用组件，通过 props 注入不同的 `phases`、`logLines`、`title` 和 `children`（结果内容），三个 Feature 各自定义自己的管线配置和结果 UI。

## 4. PipelineRunner 组件设计

### 4.1 状态机

```
NOT STARTED (-2)  →  [点击 RUN PIPELINE]
     ↓
  RUNNING (phases 0..N)  →  [所有阶段完成]
     ↓
  COMPLETED  →  [600ms 延迟]  →  展示 children（结果内容）
```

### 4.2 Props 接口

| Prop | 类型 | 说明 |
|------|------|------|
| `phases` | `{label, duration}[]` | 阶段名称和持续时间(ms) |
| `logLines` | `{time, text, type, delay}[]` | 终端日志行（含延迟、类型、颜色） |
| `onComplete` | `() => void` | 管线完成回调（触发结果展示） |
| `title` | `string` | 管线标题 |
| `subtitle` | `string` | 完成页面副标题 |
| `children` | `ReactNode` | 完成后展示的结果内容 |

### 4.3 视觉结构

```
┌──────────────────────────────────────────────┐
│  ● READY/RUNNING/COMPLETE  |  title  |  ▶ RUN│  ← Header
├──────────────────────────────────────────────┤
│  ○ 初始化模板 → ○ 加载分布 → ● 批量生成 → ...│  ← Phase 指示器
├────────────────────────────┬─────────────────┤
│  15:30:01 [INFO]  ...      │                 │
│  15:30:02 [INFO]  ...      │   旋转动画/      │
│  15:30:03 [SUCCESS] ...    │   手机模型/      │
│  █                         │   图表轮播       │  ← 右侧视觉面板
├────────────────────────────┴─────────────────┤
│  (完成后) ✓ Pipeline Complete               │
│  ↓ 600ms 后淡入 children                    │
└──────────────────────────────────────────────┘
```

## 8. 关键技术决策与注意事项

### 8.1 中文文件名处理

**问题**: `run_demo.py` 中硬编码英文文件名（`feature1_persona.py`），但实际文件是中文名。

**解决**: 修改为实际中文文件名。在 Windows 系统下中文路径通常没问题，但需要注意 Python 脚本中的 `__file__` 相对路径计算。

### 8.2 非交互模式运行

**问题**: `run_demo.py` 原设计为交互式（`input()` 等待用户按回车继续），但通过 Bash 工具执行时无法提供 stdin。

**解决**: 将所有 `input()` 替换为 `time.sleep(1)`，实现自动顺序执行。

### 8.3 UTF-8 BOM 编码

CSV 文件使用 UTF-8 BOM 编码，确保 Excel 直接打开时中文不乱码。前端下载链接直接指向此文件即可。

### 8.4 截图路径差异

Feature 2 的 `任务模拟.py` 使用 `os.path.join(os.path.dirname(__file__), "..", "output", "screenshots")` 计算路径，导致截图保存到 `D:\claude code test\output\screenshots\`（项目根级），而非 `demo/output/screenshots/`。

### 8.5 端口配置

| 服务 | 端口 | 说明 |
|------|------|------|
| Vite Dev Server | 5173 | 前端开发 |
| Flask Mock APP | 5099 | Feature 2 后端 |

### 8.6 纯前端无后端

三个 Feature 的管线动画是纯前端模拟——使用 `setTimeout` 控制时序，日志内容为预写文本。真正的 Python 脚本需要单独在终端运行。前端只展示 Demo 的**产出结果**（CSV下载、PNG图表、截图）。

### 8.7 无第三方图表库

所有图表（柱状图、饼图、漏斗图、雷达图）均使用 CSS/SVG 手写，不依赖 Chart.js 或 ECharts。这保持了包体积的最小化，并与 moss 主题完全一致。

### 8.8 Tailwind 自定义配置

在 `tailwind.config.js` 中扩展了：
- **字体**: DM Serif Display (展示), Noto Serif SC (正文), JetBrains Mono (数据/代码)
- **色板**: moss 系列 (bg/surface/card/accent/text/muted/danger/warning/success)
- **动画**: fade-up, grow-bar, pulse-dot, count-in

### 8.9 响应式设计

- 桌面端: 终端面板 + 右侧视觉面板 并排
- 移动端: 终端面板 + 视觉面板 上下堆叠
- `useDeviceDetect(768)` hook 判断断点

## 10. 设计理念总结

### 美学方向: "数字苔藓" (Digital Organism)

- **色彩**: 深绿黑底 (`#080A08`) + 苔藓绿强调 (`#7FA36B`) + 暖白文字 (`#F2F2E8`)
- **字体**: 衬线展示体 (DM Serif Display / Noto Serif SC) + 等宽数据体 (JetBrains Mono)
- **质感**: SVG 噪声纹理 overlay (opacity 0.015) + 毛玻璃效果 + 发光边框
- **动效**: 有机脉冲 + 弹性弹簧 + 交错淡入 (staggered reveals)
- **空间**: 非对称布局 + 大量留白 + 细线分隔

### 交互理念: "先演示过程，再展示结果"

所有三个功能模块遵循统一的"管线执行 → 结果呈现"模式，让系统看起来像一个真正在运行的分析平台，而非静态数据看板。用户点击 RUN PIPELINE 后看到的终端日志动画增加了技术可信度和观赏性。
