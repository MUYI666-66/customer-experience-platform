# 中国移动客户体验分析平台 — 设计思路与使用指南

## 一、项目背景与需求分析

### 原始需求

| 评分项 | 要求 | 分值 |
|--------|------|------|
| 功能点1 | 大规模合成用户生成：自动生成成百上千个不同用户画像(Persona) | 2分 |
| 功能点2 | 交互式任务模拟：模拟在中国移动APP上进行点击、搜索、多页面跳转等操作，完成咨询移动产品资费 | 2分 |

## 二、架构设计思路

### 2.1 技术选型分析

| 需求 | 候选方案 | 最终选择 | 理由 |
|------|---------|---------|------|
| 用户生成 | LLM API / Faker库 / 纯Python | **纯Python+随机分布** | 无需外部API依赖，离线可用，批量速度快 |
| APP模拟 | 真实APP自动化 / Selenium / Playwright | **Flask Mock + Playwright** | 真实APP需认证/反爬，Mock方案可控且能完整演示 |
| 可视化 | Plotly / ECharts / Matplotlib | **Matplotlib** | 已安装，静态图表足够满足演示需求 |
| 视频录制 | OBS / Selenium录屏 / ffmpeg | **ffmpeg gdigrab** | 轻量无依赖，命令行可自动化 |

### 2.2 为什么不用真实中国移动APP

1. **认证门槛**：中国移动APP需要真实手机号+验证码登录
2. **反自动化**：生产APP通常有反爬/反自动化检测
3. **不可控**：UI随时可能变化，导致演示失败
4. **合规风险**：自动化操作生产系统可能违反ToS

Mock方案的优势：页面结构固定、交互路径可控、可完整展示所有操作步骤。

## 三、功能点1 设计思路：大规模合成用户生成

### 3.1 核心问题

如何生成**合理、多样、可分析**的合成用户画像数据？

### 3.2 设计方案

**画像模板化**：定义6种典型用户画像，每种画像是一组统计分布参数：

```
用户画像 = {
    人口统计分布(年龄范围, 性别权重),
    消费行为分布(ARPU范围, 流量使用, 通话量),
    偏好特征集合(感兴趣功能, 渠道偏好,
    设备偏好),
    体验指标分布(满意度, 流失风险)
}
```

**生成算法**：
1. 按画像权重 `weighted_choice()` 分配画像类型
2. 在画像参数范围内用 `random.uniform/gauss/expovariate` 生成具体值
3. 从预定义字典中随机抽取离散属性（省份、设备、套餐等）

**关键设计决策**：
- 使用加权随机而非均匀随机 → 画像分布更自然
- 满意度用不同权重区分 → 模拟真实世界中不满意用户是少数
- 属性之间保持语义一致性 → 商务精英的ARPU不会低至18元

### 3.3 6种用户画像详解

```
商务精英 (15%): 28-55岁, ARPU ¥128-588, 高频通话+国际漫游
潮流青年 (25%): 16-28岁, ARPU ¥38-128, 大流量+视频会员
家庭用户 (22%): 30-50岁, ARPU ¥88-238, 共享套餐+宽带融合
银发一族 (13%): 55-80岁, ARPU ¥18-58,  语音为主+健康服务
学生群体 (15%): 12-22岁, ARPU ¥18-58,  校园流量+学习免流
蓝领工人 (10%): 22-50岁, ARPU ¥38-98,  语音优惠+务工套餐
```

### 3.4 输出字段 (16个)

| 分类 | 字段 |
|------|------|
| 标识 | user_id |
| 画像 | persona_type |
| 人口 | gender, age, province, city |
| 业务 | tenure_months, arpu_yuan, data_usage_gb, call_minutes |
| 偏好 | current_plan, device, preferred_channel, interested_features |
| 体验 | satisfaction, churn_risk, interaction_count, last_interaction_days |

## 五、功能点3 设计思路：旅程可视化与断点分析

### 5.1 核心问题

如何**自动**从旅程数据中识别出薄弱环节和高流失点？

### 5.2 分析模型

**5.2.1 旅程阶段模型**

将客户生命周期分为7个递进阶段：
```
认知发现 → 信息搜索 → 比较评估 → 购买办理 → 使用体验 → 客服咨询 → 续费/流失
```

**5.2.2 触点-满意度矩阵**

每个阶段定义4个触点，每个触点记录：
- 访问量 (volume): 代表该触点的流量大小
- 满意度 (satisfaction: 1-5): 代表用户体验好坏
- 渠道类型 (type): digital/social/offline/phone/core

**5.2.3 漏斗分析**

```
认知发现: 1000人 ──35%流失──→ 信息搜索: 650人 ──35%流失──→
比较评估: 420人 ──33%流失──→ 购买办理: 280人 ──11%流失──→
使用体验: 250人 ──28%流失──→ 客服咨询: 180人 ──22%流失──→
续费/流失: 140人 (整体转化率 14%)
```

**5.2.4 薄弱环节识别规则**

```python
薄弱环节 = {
    流失率 > 30% AND 影响大量用户 → 高优先级
    满意度 < 3.0              → 中等风险
    流失率 > 20%              → 需要关注
}
```

### 5.3 4张可视化图表设计

#### 图1: 旅程全景地图 (`journey_map_overview.png`)
- **类型**: 气泡图 + 阶段背景色
- **X轴**: 7个旅程阶段
- **Y轴**: 触点展示（4行/阶段）
- **气泡大小**: 触点访问量
- **气泡颜色**: 满意度（红<3.0 / 橙3.0-3.5 / 绿>3.5）
- **阶段背景色**: 该阶段平均满意度
- **目的**: 一目了然看到哪个阶段哪个触点有问题

#### 图2: 转化漏斗 (`funnel_analysis.png`)
- **类型**: 漏斗图 + 流失率标注
- **展示**: 从1000→140人的逐步流失
- **颜色**: 红色=高风险节点, 橙色=中等, 绿色=安全
- **目的**: 直观展示用户在哪里流失最多

#### 图3: 薄弱环节分析 (`pain_point_analysis.png`)
四合一子图：
- **左上**: 各阶段流失率柱状图
- **右上**: 痛点影响矩阵（散点图，X=流失率, Y=影响程度）
- **左下**: 满意度趋势对比（数字渠道 vs 线下渠道 vs 综合）
- **右下**: 改进建议优先级排序（Top 5问题+根因+建议）

#### 图4: 流失预测 (`churn_prediction.png`)
- **左**: 5级风险用户构成饼图
- **右**: 未来2个月流失趋势预测折线图（含预测区间高亮）
- **目的**: 预警未来风险

### 5.4 "AI分析" 的实现

当前采用的是**规则引擎 + 数据驱动**的分析方式，模拟AI分析的效果：

```
输入: 旅程各阶段的满意度、流失率、触点数据
      ↓
分析引擎:
  1. 计算各阶段流失率 → 排序 → 找出Top5高流失阶段
  2. 关联触点满意度 → 识别低分触点
  3. 预设问题知识库 → 匹配根因和建议
      ↓
输出: 结构化的分析报告文本
```

如需真正的AI分析，可以在 `PAIN_POINTS` 数据生成环节接入LLM API，由模型动态分析数据并生成报告文本。

## 六、视频录制方案

### 6.1 技术方案

```
ffmpeg -f gdigrab    ← Windows屏幕采集
       -framerate 10  ← 10fps (演示足够，减文件大小)
       -i desktop     ← 捕获整个桌面
       -t 600         ← 最长10分钟
       -c:v libx264   ← H.264编码
       -preset fast   ← 快速编码
       -crf 24        ← 较好画质
       -pix_fmt yuv420p ← 兼容所有播放器
       output/demo_video.mp4
```

### 6.2 录制策略

选择**全桌面录制**而非单个窗口录制，原因是：
- 功能点2 Playwright 会打开独立浏览器窗口
- 功能点3 Matplotlib 会弹出独立图表窗口
- 全桌面录制能捕获所有窗口切换和弹窗效果

### 6.3 自动化流程

```
record_and_run.ps1:
  1. Start-Process ffmpeg (后台录制)
  2. python run_demo.py (前台演示)
  3. Stop-Process ffmpeg (停止录制)
  4. 检查视频文件大小/时长
```

## 七、踩坑记录与解决方案

### 7.1 Windows GBK 编码问题

**问题**: Python 脚本中的 emoji (如 📊🔍✅) 触发 `UnicodeEncodeError: 'gbk' codec can't encode character`

**解决**: 在每个脚本顶部添加：
```python
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
```

### 7.2 Matplotlib Alpha 值越界

**问题**: 满意度最高 4.2 时，`alpha = 0.6 + 4.2/10 = 1.02 > 1.0` 导致 ValueError

**解决**: 改为 `alpha = min(0.95, 0.5 + satisfaction/10)`

### 7.3 Matplotlib 中文字体

**问题**: Windows 上默认字体不支持中文

**解决**: 自动探测系统字体路径，优先使用微软雅黑：
```python
for fp in ["C:/Windows/Fonts/msyh.ttc", "C:/Windows/Fonts/simhei.ttf"]:
    if os.path.exists(fp): FONT_PATH = fp
```

### 7.4 进度条在 Bash 中不换行

**问题**: `\r` 回车符在 Bash 终端中不会覆盖当前行，导致输出大量进度条行

**分析**: 这是终端模拟器差异，不影响功能。在原生 Windows CMD/PowerShell 中正常。可以接受，或改用 `tqdm` 库解决。

## 八、使用步骤

### 步骤 1: 检查环境

```powershell
# 确认 Python 版本 (需 3.10+)
python --version

# 确认 ffmpeg 可执行
ffmpeg -version

# 确认依赖已安装
pip install flask matplotlib numpy pandas playwright
playwright install chromium
```

### 步骤 2: 运行演示 (不录制)

```powershell
cd "d:\claude code test"
python demo/run_demo.py
```

操作流程：
1. 看到欢迎界面 → 按 Enter
2. 功能点1 自动运行（生成800个用户） → 按 Enter
3. 功能点2 启动Mock服务器 → 按 Enter
4. Playwright 打开浏览器自动操作（约30秒） → 按 Enter
5. 功能点3 生成4张图表并依次展示 → 完成

### 步骤 3: 录制视频

**方式A - PowerShell一键录制（推荐）**:

```powershell
powershell -ExecutionPolicy Bypass -File "demo/record_and_run.ps1"
```

这会自动：
- 启动 ffmpeg 录制整个桌面
- 运行三个功能点演示
- 演示结束后自动停止录制
- 输出 `demo/output/demo_video.mp4`

**方式B - 手动录制**:

```powershell
# 终端1: 启动录制
cd "d:\claude code test"
demo\record_demo.bat
# 立即切换到终端2...

# 终端2: 运行演示
cd "d:\claude code test"
python demo\run_demo.py
```

### 步骤 4: 单独运行某个功能点

```powershell
# 只运行功能点1
python demo/feature1_persona.py

# 只运行功能点2 (需要先启动服务器)
# 终端1:
python demo/feature2_app/mock_app.py
# 终端2:
python demo/feature2_simulate.py

# 只运行功能点3
python demo/feature3_journey.py
```

### 步骤 5: 查看输出

```
demo/output/
├── synthetic_users.csv          # 功能点1输出: 800个用户数据
├── interaction_log.jsonl        # 功能点2输出: 交互日志
├── screenshots/                 # 功能点2输出: 12张操作截图
├── journey_map_overview.png     # 功能点3输出: 旅程全景地图
├── funnel_analysis.png          # 功能点3输出: 转化漏斗
```

### 步骤 6: 录制注意事项

1. **关闭无关窗口** - 保持桌面整洁，展示效果好
2. **不要操作鼠标** - 录制期间鼠标光标会被捕获
3. **确保分辨率** - 建议 1920×1080 或更高
4. **视频时长** - 硬限制600秒(10分钟)，超过会自动截断
5. **文件大小预估** - 10fps录制10分钟约 50-80MB
6. **如需录制特定窗口** - 修改 ffmpeg 参数中 `-i desktop` 为 `-i title="窗口标题"`
